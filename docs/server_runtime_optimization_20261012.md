# 运行性能优化与复核（2026-10-12）

依据 `reports/server_lag_audit_20261012.md` 的远端证据，处理实时连接生命周期、关闭后的推送竞争和后台培养长尾。本轮完成本地代码及验证，尚未部署。保留工作区其他已有改动，不提交代码或改变数据库结构。

## Findings

- High，已处理：页面退出或后退缓存时聊天/通知连接未显式释放，可能持续占用容量；失败重连仍频繁发起。复核已有前端改动，保留 `pagehide/pageshow` 的连接释放、恢复及迟到事件隔离，持续失败退避上限改为 60 秒；另修复聊天断线后点击发送绕过待执行重连计时的问题。
- Medium，已处理：在线人数日志出现 `Attempt to send on a closed protocol`。三个消费者共用的 session guard 记录关闭状态，关闭后跳过推送和业务消息，但仍处理 disconnect 并回收额度。仅捕获 Daphne/Autobahn 明确的 `Disconnected`；编程和序列化错误继续上抛。Channels 的 `send_json` 会通过 `super().send` 绕过 mixin 的 send，因此显式将 JSON 发送转交本层保护路径，并用三个消费者的测试验证。
- Medium，已缓解：竞技场储备培养一轮串行推进多个成员、多个槽位，近两天最长 147 秒。周期任务默认增加 20 秒软预算，仅在完整 claim → 领域动作 → finalize → 持久下次到期时间之后判断是否暂停，下一扫描继续原轮次。直接调用 service 默认保持原不限时行为，周期任务显式传入预算。
- Medium，继续观测：虚拟维护最长约 89 秒，其批次会提前创建安全记录及规划快照，不能直接中断。新增完成结算、招募、维护三阶段耗时，保留安全记录的完整提交方式。耗时放进普通日志 message，避免只加 extra 而当前 formatter 不显示。
- Low，已处理：实时容量拒绝日志 extra 中有原因及槽数，但普通文本不显示。拒绝消息直接附带原因、活动槽数和限额，保留原结构化字段；不额外输出原始公网 IP。

## Boundary governance

- 前端控制器拥有 socket、心跳、重连与稳定计时器；页面退出清理，恢复不会创建重复连接，旧事件不影响新 socket。
- transport 层处理关闭协议的生命周期竞争；会话、Origin、用户和 IP 容量校验保持原边界，没有移除保护，也没有新增“异常时绕过校验”。
- 培养 service 保持业务 claim、资产及槽位更新所有权；任务层提供运行预算，预算判断在完整事务步骤之间，不把资产处理移到前端或队列控制器。
- 维护扫描仍拥有完整的安全流程，本轮只观测阶段，不强制 break。

## Refactor plan

保留已有领域规则和服务接口兼容性；复核未上线的前端生命周期改动并修补退避入口；在已有共享 session guard 中增加关闭保护；为培养 service 增加可选软预算，由周期任务启用；补充必要的运行日志。本轮没有新增共享标签页协议、队列、依赖或数据库迁移。

## Scope assessment

Surgical Fix：以局部生命周期与安全步骤之间的让出为主，不进行架构迁移。

## Verification

- 前端相关 71 项实际 Node 用例通过，生产 JS 和相关测试 ESLint 通过。覆盖页面退出、后退恢复、旧事件、重复连接、离线重复发送、退避状态、终止码和待确认聊天消息。
- 实时通道相关 143 项回归通过，默认环境跳过的 3 项随后在独立真实 Redis 上全部通过。覆盖三种消费者的服务器关闭、客户端断开、关闭中推送竞争、disconnect 出错仍回收、关闭状态的实例隔离、会话终止与容量保护。
- 后台培养、任务及安全扫描相关 151 项通过。覆盖暂停后的 claim 清理、无未完成培养预算条目、同轮剩余槽位续跑、零 limit、等待更久成员优先，以及普通文本日志可见阶段耗时。
- 分批状态清理、续跑和公平性 3 项另在本地隔离 MySQL + 独立临时 Redis 验证通过。
- Black、flake8、相关 isort 与前端 ESLint 检查通过；两个 WebSocket 生产文件的目标 mypy 通过；相关变更空白检查通过。

测试没有读取或修改远端玩家数据，没有重启远端服务。本轮未测得部署后的实际拒绝率及延迟改善，不能以本地测试代替上线后趋势。

## Residual risk

- 20 秒为软预算：单次不可分割的领域动作超过预算时仍需完整结束。已开始的选取和数据库查询也不会被强行取消，不能承诺任务总耗时严格不超过 20 秒。
- 预算耗尽时尚未执行的成员可暂留原有的一分钟批次入场预算；没有新 claim 或安全 attempt，也没有扣资产，原期限过后继续扫描。不能为了立即撤销该预算破坏并发限流。
- 多用户共用公网 IP 或大量合法标签页仍可能达到 20/12 的容量上限；生命周期和退避能减少不必要占用与重试，不能保证消除所有拒绝。跨标签页共享连接属于后续单独设计。
- 本轮没有宣称修复招募/训练死锁；此前重试均成功，后续需结合锁图和阶段耗时治理关联模板锁与锁顺序。
- 虚拟维护主批次仍可能有长尾，应根据新增的阶段耗时确定拆分位置，避免遗留安全记录。
- 48 小时日志保留、慢 SQL 观测以及健康检查后代理切换的发布方式仍需单独落地；当前没有更改生产日志和发布配置。
