# 帮会资源与任务界面重设计

## 背景

当前帮会相关界面存在三个明显断层：

1. [`guilds/templates/guilds/resources.html`](/home/daniel/code/web_game_v5/guilds/templates/guilds/resources.html) 只展示银两、粮食、金条，缺少红宝石与护院信息，资源视图不完整。
2. [`guilds/templates/guilds/donate.html`](/home/daniel/code/web_game_v5/guilds/templates/guilds/donate.html) 只支持银两、粮食捐赠，和资源页、护院捐赠页分裂，用户需要在多个页面之间跳转。
3. [`guilds/templates/guilds/missions.html`](/home/daniel/code/web_game_v5/guilds/templates/guilds/missions.html) 当前是简单列表 + 内嵌表单，交互方式与个人任务页 [`gameplay/templates/gameplay/tasks.html`](/home/daniel/code/web_game_v5/gameplay/templates/gameplay/tasks.html) 不一致，且页面中额外存在“帮会护院池”区块，信息组织偏散。

这次调整的目标是把帮会资源页和帮会任务页作为一套统一界面重构：资源页负责“看库存、做捐赠”，任务页负责“看任务、选门客护院、发起出征”。

## 目标

1. 在帮会资源区域完整显示银两、粮食、金条、红宝石以及护院详情。
2. 把资源捐赠区统一扩展为银两、粮食、金条、护院四类捐赠。
3. 帮会任务页参考个人任务页的分页表格、详情弹层、门客卡片选择和护院滑杆配置交互。
4. 去除帮会任务页中的“帮会护院池”独立区块，避免重复展示。
5. 复用现有后端服务和前端样式，控制回归范围。

## 约束条件

1. 不新增新的帮会资源模型字段来存红宝石，继续沿用帮会仓库中的 `red_ruby` 库存作为来源。
2. 不重写护院捐赠核心服务，继续复用 [`guilds/services/guild_troops.py`](/home/daniel/code/web_game_v5/guilds/services/guild_troops.py)。
3. 不改动帮会任务的发起、撤回、结算主业务流程，只调整页面组织和表单结构。
4. 保留现有路由名，不破坏已有入口和测试。
5. 不执行 git commit；仓库内规则要求未经用户明确要求时不进行提交操作。

## 方案

### 资源页重构

资源页改成“总览 + 捐赠”双核心结构：

1. 顶部资源总览区显示 4 张资源卡：银两、粮食、金条、红宝石。
2. 同一区域增加护院概览卡，显示：
   - 护院总数
   - 护院种类数
   - 前几种护院摘要
3. 在护院概览下方直接展示完整护院明细列表，包含护院名称、标识或头像、当前库存。
4. 保留贡献统计区，但把资源页重点从“静态展示”调整为“库存 + 操作”。

红宝石不从 `Guild` 模型字段读取，而是从帮会仓库里聚合 `item_key="red_ruby"` 的数量。这样与帮会任务奖励结算和帮会科技消耗路径保持一致。

### 捐赠区整合

资源页内直接承接统一捐赠区，替代当前分裂的资源捐赠与护院捐赠入口。

#### 银两 / 粮食 / 金条

统一走 [`guilds/services/contribution.py`](/home/daniel/code/web_game_v5/guilds/services/contribution.py) 的资源捐赠服务扩展版本：

1. 保留现有事务和锁顺序，继续使用并发安全模式。
2. 在现有 `silver`、`grain` 基础上新增 `gold_bar` 支持。
3. 金条捐赠需要包含：
   - 玩家库存校验
   - 单次捐赠数量校验
   - 帮会入账
   - 贡献度增长
   - 捐赠日志和资源流水记录
4. 在 guild contribution 常量中明确补齐 `gold_bar` 的贡献倍率和每日限制配置，使金条捐赠与银两、粮食走同一套规则入口。

#### 护院捐赠

护院捐赠入口从任务页迁移到资源页的统一捐赠区，但后端仍沿用 [`guilds/views/missions.py`](/home/daniel/code/web_game_v5/guilds/views/missions.py) 中 `donate_troops` 对应的服务逻辑：

1. 表单提供护院类型与数量输入。
2. 视图层可以保留现有路由与处理函数，避免破坏外部入口。
3. 页面入口只保留在资源/捐赠区域，不再在任务页重复出现。

### 帮会任务页重构

帮会任务页参考个人任务页进行结构调整，但保持帮会业务语义：

1. 页面顶部保留“当前出征状态卡”，显示任务名、倒计时、当前派出门客数，以及管理员/帮主的撤回按钮。
2. 任务列表改成与个人任务页一致的分页签 + 表格模式：
   - 分页签固定按任务模板的 `difficulty` 字段分为初级 / 中级 / 高级
   - 每行显示任务名称、类型、奖励/消耗标签、操作按钮
   - 点击“详情”进入任务详情层
3. 原页面中的“帮会护院池”整块删除，不再单独展示。
4. 原页面中的“出征门客”独立区块删除，相关信息转移到任务详情层中做选择和理解。

### 任务详情层交互

任务详情层贴近个人任务页已有模式：

1. 左侧显示任务情报：
   - 任务描述
   - 奖励信息
   - 门客数量建议
   - 是否允许护院
   - 耗时信息
   - 敌方情报（如现有模板提供）
2. 右侧显示出征配置：
   - 门客选择改为卡片多选，显示头像、名称、等级、血量
   - 数据来源不是全部空闲门客，而是“当前帮会上阵门客”
   - 护院选择改为每种护院一行，使用滑杆 + 数字输入联动
3. 发起按钮状态与现有规则一致：
   - 已有进行中的帮会任务时禁用
   - 没有可选门客时禁用
   - 不可携带护院的任务不渲染护院配置区

### 数据分组策略

个人任务页按初级/中级/高级分页。`GuildMissionTemplate` 已定义 `difficulty` 字段，因此帮会任务页也固定按 `junior`、`intermediate`、`advanced` 三组渲染分页签，不引入额外的分组推导逻辑。

## 错误处理

1. 金条捐赠沿用现有资源捐赠错误链路：
   - 资源类型非法
   - 数量非法
   - 库存不足
   - 超出每日限制
2. 护院捐赠继续使用现有错误语义，例如“护院参数错误”“数量不足”。
3. 帮会任务详情层中，如果没有可选门客或护院，直接渲染空状态提示，并禁用提交按钮，避免用户操作后才失败。
4. 任务发起后的服务层校验保持不变，前端限制只做体验增强，不替代后端校验。

## 样式与前端复用

1. 复用个人任务页已有的表格、分页签、详情弹层、门客选择卡片、护院滑杆样式与脚本。
2. 资源页新增最少量样式，补齐：
   - 四资源卡 + 护院概览卡的混排布局
   - 护院明细列表
   - 四类捐赠卡或统一捐赠栅格
3. 帮会任务页只在必要处增加帮会专属文案与状态展示，不另造一整套视觉体系。

## 验证流程

实现完成后至少验证以下内容：

1. 金条捐赠服务/视图测试：
   - 成功捐赠
   - 数量非法
   - 金条不足
   - 日限制或配置限制
2. 资源页渲染测试：
   - 正确显示红宝石数量
   - 正确显示护院概览与明细
   - 渲染四类捐赠入口
3. 帮会任务页测试：
   - 页面不再出现“帮会护院池”区块
   - 任务列表改为分页表格结构
   - 详情层出现门客卡片选择和护院配置输入
4. 回归测试：
   - 现有帮会任务发起/撤回测试继续通过
   - 现有护院捐赠测试根据入口迁移做最小调整

## 风险与缓解

1. 金条捐赠需要补齐配置和库存读取逻辑，若处理不一致，可能导致贡献计算或资源扣减不统一。
   - 缓解：严格复用现有资源捐赠事务结构，只对资源类型做扩展。
2. 红宝石来自仓库而非帮会字段，资源页与仓库页可能存在显示来源不一致风险。
   - 缓解：资源页只读取仓库聚合结果，不引入第二套红宝石来源。
3. 帮会任务模板难度字段若不存在，直接复刻个人任务页的三档分页会失真。
   - 缓解：先检查模板字段，再决定是按难度分页还是按现有模板分组分页。
4. 页面重构后，现有前端脚本可能同时影响个人任务页和帮会任务页。
   - 缓解：复用脚本时通过明确的选择器和数据属性隔离页面行为。
