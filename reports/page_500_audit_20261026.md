# 页面偶发 500 排查（2026-10-26）

本轮仅只读检查线上日志、连接状态和 Web 源文件，未重启或修改服务。

## 确认的原因

存在浏览器实际收到的 HTTP 500，不只是应用将取消请求记为 500。门客列表请求在加载登录会话时无法建立 MySQL 连接，底层异常为 `OperationalError: (1040, 'Too many connections')`。其他页面也存在同类故障；这说明至少这些已核对事件发生在公共会话/认证路径，无需进入具体门客逻辑即可失败。

北京时间 06:50:37、07:12:00 附近的门客列表错误堆栈均含 MySQL 1040 和 `django/contrib/sessions/backends/db.py`。同一请求可能因错误处理和访问日志再次访问惰性加载的 `request.user` 而出现多层异常，不应将 traceback 行数或重复错误日志当作独立请求次数。`SessionStore` 的 `_session_cache` AttributeError 是正常懒加载过程中被后续异常带入堆栈的上下文，不能据此认定 SessionStore 缺少属性是根因。

Caddy 保留窗口约为北京时间 05:43:25–09:52:42，其中门客列表 `/guests/` 有 23 次实际 HTTP 500，另有招募、疗伤及其他操作的 500。最新列表错误包括 08:45:34、08:45:35，代理耗时约 24ms、17ms。连接数耗尽会直接拒绝新连接，因此可以很快返回 500，而非总表现为长时间等待。

Web 日志保留窗口与 Caddy 不同，起点约为北京时间 02:42:23。两个窗口的请求数不能直接互相比较。Web 应用记录中另有 CancelledError，仍需与代理状态区分；不能把全部 500 或取消事件都归为相同原因。

## 线上修复状态

- Web 环境 `DJANGO_DB_CONN_MAX_AGE=60`。
- `/app/config/asgi.py` 尚无本地新增的 ASGI 持久连接禁用逻辑，即前一轮修复尚未上线。
- 本轮 MySQL 快照：34 个连接、2 个运行线程、33 个 Sleep 会话，最长 Sleep 77 秒；不是采样时持续满连接。
- 连接上限拒绝累计值为 4742，前一轮 10 月 25 日 23:59 前采样为 369。这是服务累计计数，不能将 4742 称作本轮窗口独立报错请求数。
