# 装备属性与前缀转换评估（2026-10-17）

本文件保留最初的现状审计；其中候选调整范围已由同目录 `equipment_optimization_design_20261017.md` 的v2方案替代。当前方案按流派收紧属性，并将跨品质装备及套装的额外带兵预算控制在500。

## 评估口径

本次为分析，不修改游戏配置、业务代码或数据库。依据当前仓库 YAML 和战斗运行代码，不以历史装备目录或旧注释为准。

- 当前静态装备模板共265件：白27、绿63、蓝66、紫67、橙42；其中34件属于当前商铺装备。灵魂容器本身是工具，不计入装备；其动态生成的灵魂饰品也不在此静态目录内。
- 门客比较采用可招募、非隐士英雄模板的成长数学期望；每名英雄使用自身成长区间、成长权重及基础属性配置，然后取同品质同类型的中位数。
- 成长估算不包含装备、套装、招募随机偏差、玩家自由加点、洗髓或特殊道具；不是线上玩家实测分布。
- 本地预览库只有27名门客，且21名橙色门客均为1级，不能代表真实玩家养成情况；未查询生产数据库。
- 装备槽位为头、衣、鞋、武器、坐骑各1，饰品3、器械3。同名装备不可重复装备。

## 属性实际作用

| 属性 | 当前运行行为 | 对装备设计的含义 |
| --- | --- | --- |
| 武力 | 武将每点贡献0.7攻击，文官0.5；部分技能按武力计算 | 不能与面板攻击等价；适合武将武器的主要预算 |
| 智力 | 武将每点贡献0.3攻击，文官0.5；参与技能增伤和部分敌方技能扣减 | 不是独立法攻体系；文官装备必须结合运势、技能公式评估 |
| 防御 | 每点增加1防御，同时增加50生命；防御参与减伤 | 兼具血量和减伤，价值明显高于裸数字表现 |
| 敏捷 | 影响通常出手顺序、相关先攻机制、部分技能和学习要求；不增加基础暴击或闪避 | 属于门槛收益，超过对手后继续增加不必然提高普通攻击收益 |
| 生命 | 直接增加生命 | 与防御比较时必须考虑防御额外提供的50生命及减伤 |
| 运势 | 主动技能逐项判定概率为 clamp(0.95 × (运势/300)^0.85, 5%, 95%)；一回合最多选出一个主动技能 | 对多主动技能组合和文官非常重要，不能作为低价值杂项 |
| 带兵数 | 增加出战容量，不直接生成护院 | 需要家丁、装备、招募时间与实际兵源才能兑现，可单列更宽松预算 |

当前第4版引擎通常回合优先按护院、门客分组，再比较敏捷；不能把高敏装备解释为必定抢在护院之前行动。

对门客普通伤害有15倍系数，技能额外伤害另按2倍结算；门客对护院普攻也有15倍屠戮系数，技能额外部分独立计算。暴击基础概率5%，不能把智力简单判断为无用，也不能假定主属性越高技能收益就必然同比例提高。

## 当前结构问题

### 1. 橙色武器的输出定位被生命预算挤占

武器主属性均值：绿武力19.6、蓝35.1、紫48.6、橙41.8；对应平均生命22.5、125.8、91.3、592.6。

例如紫屠龙刀为271生命、77武力，橙轩辕剑为538生命、7防御、33武力、29智力、14运势。对武将，前者贡献约53.9普攻攻击，后者约31.8；后者更均衡，但品质提升不代表输出提升。橙玄铁重剑58武力，也低于部分紫武器。

这不证明所有橙武器较弱，但说明橙色输出武器缺少稳定的职责升级感。建议按输出、智力技能、均衡等定位逐件复审，优先补核心属性，必要时削减杂项生命，而非全部数字同时放大。紫色特色武器可以保留专精优势，不能让整个橙色武器群体依靠生命补评分。

### 2. 生存预算需要统一口径

紫玄武甲676生命、48防御，仅本体就贡献3076生命；橙软猬甲665生命、46防御，贡献2965生命。软猬甲另有28敏捷，不能只据生命判弱，但升品确实表现为速度取舍。

玄武四件本体共1933生命、135防御；套装再加260生命、70防御、20武力。合计获得12443生命、205防御、108武力、17智力、30敏捷。70级紫武将裸体防御中位数约200，单这四件就能再增加205防御。

这体现坦克套装特色，也说明生命与防御一起堆叠时影响很大。建议先保持每点防御提供50生命的核心公式，按“生命 + 50×防御”核算血量，再单独检查减伤；不要用裸属性总和判断价值。

### 3. 带兵加成的品质曲线明显断层

- 绿玉佩：50生命、100带兵。
- 蓝龙纹玉佩：100生命、12武力、50带兵、15运势。
- 紫色14件饰品全部没有直接带兵加成；全紫装可凑出的直接带兵上界仅39，来自霸王枪。
- 橙传国玉玺200带兵、江湖令100带兵，重新出现高容量。
- 蓝校尉四件本体90带兵，套装另100，合计190。

按每个槽位选不同模板、每项属性分别最大化，不计套装，同品质装备直接带兵理论上界为绿186、蓝170、紫39、橙344；它们不是同一套通用最优配装，也不代表获得难度相同。

因此同意放宽带兵预算，优先补齐蓝紫色统兵装备，再提高高品质专精装备，而非压低绿玉佩。

### 4. 旧评分与约束不足以指导新平衡

现有装备测试评分为：生命/54 + 武力 + 智力 + 防御 + 敏捷 + 1.2×运势 + 带兵/2。它没有表达防御的完整生存收益、敏捷门槛、文武差异、技能触发组合和带兵的兑现成本。

现有测试还把全槽直接带兵限制在520，并将橙装非生命数值相加限制到260。若提高带兵，这些约束应随批准的设计调整；不能把它们当作已经验证的战斗平衡定律。

## 带兵调整建议（候选范围，未验证胜率）

| 专精装备 | 绿 | 蓝 | 紫 | 橙 |
| --- | ---: | ---: | ---: | ---: |
| 统兵饰品单件 | 80–120 | 140–200 | 220–320 | 350–500 |
| 统兵武器单件 | 30–50 | 60–100 | 100–160 | 160–240 |
| 统兵头盔/衣甲单件 | 20–30 | 30–50 | 50–80 | 80–120 |

范围只用于统兵定位的装备，不是所有装备都附加带兵；套装奖励另算。坐骑是否提供额外统兵可作为少量专精分支，不必全量追加。一般输出、坦克、速度装备保留各自职责。

建议先以70级单门客的统兵专精配装作为目标区间：绿总容量约400–600、蓝600–900、紫900–1300、橙1300–1800。已包含基础250容量；这是用于下一轮仿真的设计目标，不是硬上限，也不是全品质普通配装的统一待遇。

基础容量为200，70级起增加50。队伍容量按出战门客求和，5名门客每人多300容量，就可多带1500护院。护院攻击按单兵攻击乘当前兵力，受伤会减员、降低输出；高科技、兵种克制、器械也会影响收益。

当前引擎同一种护院达到1000人会分队攻击，并在相应条件下使用1.2伤害系数；分队会分摊兵力，并不是每个分队重复使用整队攻击。因此“增加带兵有成本”支持放宽额度，但不足以直接证明兵量放大数倍仍然平衡。下一轮应覆盖999/1000/1001、1999/2000/2001等人数门槛以及5/10/20名门客阵容。

## 前缀规则与当前装备的冲突

已明确的意图：除前缀目标属性外，其他属性减少20%，扣除的部分加到目标属性。

若生命、带兵与四维直接按裸数相加，会发生单位转换套利：

- 紫混元伞800生命、14防御、42武力、5运势；按每项扣除值向下取整，防御前缀扣160生命、8武力、1运势，增加169防御。结果640生命、183防御、34武力、4运势；本体贡献生命从1500变为9790，净增8290，同时减伤增强。
- 同一件混元伞的敏捷前缀可增加171敏捷；这已超过70级橙武将裸体敏捷中位数167.4。
- 若橙统兵饰品提供500带兵，单带兵这一项就能换100武力/智力/防御/敏捷；带兵越慷慨，这条转换路径越强。

因此仅调整原装备目录不能解决这一冲突。建议优先采用“四维互转20%，生命、运势、带兵与套装效果保持原值”；该建议是在缩小转换范围，需用户决定，不能当作已授权规则。

如果用户希望所有数值属性都参与，就应保留“每项减少20%”，但对扣除值按单位价值换算后再加入目标，而不是裸数直接相加；例如生命需按几十生命对应1四维点的尺度评估，具体比例不能仅凭经验立即定版。

## 建议顺序与验证

1. 先按职责复审橙色武器、生存预算与蓝紫统兵断层，形成逐件原值/新值清单。
2. 带兵独立预算，不用削掉等量主属性来机械兑换。
3. 用相同门客、相同自由点和技能、相同随机种子进行旧装/新装对照；覆盖纯门客与混合阵容、低高科技、兵种克制、护院伤亡和资源消耗。
4. 关注战斗回合数、胜率、先攻收益和战后补兵成本，确认统兵、输出、坦克、速度及文官技能流有各自使用场景。
5. 明确前缀转换范围与单位后，再实现前缀和装备实例保存，避免在未稳定的装备结构上叠加随机系统。

本轮完成了配置统计与运行公式核对，没有修改玩法或执行回归测试；尚未完成战斗仿真，以上调整区间均为设计建议。
