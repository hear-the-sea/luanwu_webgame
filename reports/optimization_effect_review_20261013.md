19:20:42 任务使用卡请求约 8 秒后被取消，同时标记邮件请求耗时约 3 秒。随后一个分钟采样记录数据盘平均 I/O 延迟 27.44ms、任务 Redis `aof_delayed_fsync` 从 169 增至 171；19:21:00 readiness 返回一次 503，之后恢复健康。整个监控期该计数最终为 172。

这些证据支持继续排查数据盘抖动与依赖任务 Redis 的请求路径，但分钟级时间相关性不是单个请求的完整因果证明。本次没有发现普通页面 Redis Timeout、真实异常 traceback 或死锁日志。后续应对慢请求补充数据库/任务发布阶段耗时，并核对云磁盘延迟；增加 Web 内存不能消除磁盘落盘延迟。

## 上线前已存在的后台安全暂停

决策审计 ID 743 确认：15:05:00，维护由 `v2_active` 转为 `v2_paused`，revision 799，原因 `duplicate_or_partial_commit`，冻结窗口为 14:00–15:00。这比本次 18:05 上线早约三小时。

逐事件配对发现 14:30 同批次有 12 条 started 缺少 terminal，以及 1 条 commit_uncertain，合计触发指标 13。该提交未知操作有 retry 恢复记录，首次失败 14:31:02；未找到对应业务 attempt 或执行 receipt。缺少回执不能单独证明所有业务状态未变，仍须核对领域事务与恢复记录，不能直接重放或清空安全标记。

此暂停同时禁止虚拟玩家维护、人口轮换和竞技场成长；当前 maintained/roll 为 0，后台任务毫秒级返回是停止业务工作的结果，不能当作吞吐优化收益。当前有 687 个 open 定时培养周期、395 个到期槽位，恢复后仍需重新观察实际负载。

正常分批预算退出不会制造 FAILED；新实现会结束已准入安全记录，减少旧长批次异常时留下 started 的范围。hard pause 不会自动恢复，必须先核对异常操作与事务边界，再使用已有受审计恢复流程；本次保留该保护状态。
