# 第二轮性能优化与验证（2026-10-01）

已完成资源粮账锁行复用，以及竞技场候选零技能／单技能门客的批量读取。运行时改动限定四个文件，公有接口、数据库结构、生产周期和战斗规则保持原样。全部验证在本地完成，本轮尚未部署。

## 实现与保留的行为

资源服务在同一次持有 Manor 锁的结算调用内复用已经锁定的粮食库存行，省去写回前的重复 SELECT。库存私有 helper 校验库存主键、所属庄园、模板 ID 与仓库位置；引用不跨调用栈或事务保存。缺行创建、旧粮字段修复、模板缺失、零粮删除、更新时间、容量限制和异常回滚保留原路径。资源事件仍在每个庄园原来的位置写入，未合并事件。

竞技场候选查询使用专用 `_arena_snapshot_skills` 预取列表。只有零个或一个技能时直接读取，因为此时顺序唯一；两个以上技能继续发送原来的 `values_list()` SQL，保留数据库隐式顺序及对应战斗随机数消耗。普通技能预取缓存仍沿原查询路径，避免改变历史比赛代码读取最新技能的时点。租用候选在获取 BotProfile 锁后重新读取门客和技能，不复用规划阶段快照。

使用现有 Django 事务、行锁和 Prefetch 实现，未增加依赖或缓存失效机制；这是减少数据库往返的局部修改。资源服务继续拥有结算事务，竞技场服务继续拥有候选锁与租用边界。

## 本地 MySQL 基准

使用已运行的 MySQL 8.4，显式连接 `127.0.0.1:13306` 的隔离 `test_bank_bulk_release_check` 库。预热后原版／优化版配对执行五次，表中耗时为中位数，排除测试补丁安装、撤销和事务清理。查询统计包含被测服务的数据库往返。

资源基准使用实际建筑、科技、人员与兵力基准读取路径，已有库存且产生粮食和银两；调用按 50 庄园分块，保持原事务边界。

| 庄园数 | SQL 原版→优化 | SELECT 原版→优化 | 耗时原版→优化 |
|---|---:|---:|---:|
| 1 | 13→12 | 8→7 | 7.243→6.627 ms |
| 50 | 258→208 | 106→56 | 141.173→110.005 ms |
| 500 | 2580→2080 | 1060→560 | 1442.077→1152.161 ms |

500 庄园场景少 500 次 SELECT，耗时约下降 **20.1%**。没有粮食增减或未建库存的分支不保证同样收益。

竞技场基准为 5 个候选庄园、30 位门客，包含完整候选查询和战斗快照构造。

| 技能分布 | SQL 原版→优化 | 耗时原版→优化 |
|---|---:|---:|
| 全部零技能 | 33→4 | 19.585→5.940 ms |
| 全部单技能 | 33→4 | 19.623→6.039 ms |
| 0／1／2／3 技能混合 | 33→18 | 19.750→12.810 ms |
| 全部三个技能 | 33→34 | 19.476→20.482 ms |

**收益有适用范围**：全员多技能时，每个非空预取批次增加一次查询，本地耗时约增加 5.2%。为保留战斗行为，本轮没有统一重排多技能列表。当前虚拟玩家低三个声望段蓝图的最高门客等级为 5／10／15，技能目标公式使其适用于零／单技能快路；没有据此推断线上实际门客分布。

以上是本地服务基准，不能直接换算为线上任务整体提速；没有新采集线上日志、任务负载或技能分布。

- **54 项 MySQL 检查通过，无跳过**：20 项资源专项、20 项竞技场专项、7 项新增资源并发、5 项既有竞技场人口与租用并发、2 项竞技场结算并发。
- **6 项 MySQL 历史独立对照通过**：原疗伤完整源码对照和原候选热点复现。
- **336 项关联回归通过**：资源／库存 118 项，工资／训练／帮派／虚拟玩家 96 项，最终竞技场快照／储备池 122 项。
- Black、isort、flake8、四个运行文件 mypy 与 diff 检查通过。

资源专项加载固定 SHA 的完整原版库存和资源模块，比较返回值、庄园字段、库存字段与事件字段，仅忽略事务回滚不会回收的库存／事件自增 ID。覆盖模板缺失、兼容字段偏差、零粮删除、缺行、容量满／超容量、无增量、正向限制、不推进时间，以及后续库存／事件写入失败时整个分块回滚。

并发测试真实执行消费／授粮、批量结算与锁等待，验证竞争后粮账守恒、重复批次只发放一次、`skip_locked` 跳过被锁庄园、缺行只创建一次、第二庄园失败回滚后等待授粮读取原账本。仅固定产出基准与线程门控，不模拟事务、账本或流水。

模板排序规则也按数据库实际行为对照：本地字段为 `utf8mb4_0900_ai_ci`，`GrAiN` 和 `gráin` 匹配 `grain`，`grain ` 不匹配。新增 helper 不再进行字符串严格比较；既有模板解析规则保持原样。尾空格未匹配时仍保留原代码的缺模板分支，不能套用其他排序规则的 PAD 预期。

竞技场测试比较完整战斗快照，打乱技能键、主键和关系插入顺序，多技能回退 SQL 与原版逐字一致；另覆盖普通预取后数据库更新、租用锁后重新读取、分块迭代、空阵容及轻量对象。两个原版对照函数的 AST 函数体已核实与修改前源码一致。

验证过程中修正了两处测试夹具预期：尾空格比较改为遵循真实列排序规则；并发用户夹具改用 `bulk_create`，避免用户信号提前创建庄园。最终完整运行全部通过。
